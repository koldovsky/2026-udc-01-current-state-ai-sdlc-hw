# A/B-эксперимент: базовый vs структурированный промпт

## Задача
Добавить счётчик количества заметок в `NotesApp` (например, "Заметок: N" над списком).

## Промпт A (базовый)

```
Добавь счётчик заметок в NotesApp
```

**Результат:**
- Изменения: +5/-1 строк в `NotesApp.tsx`
- AI сам выбрал место (между формой и списком) и текст ("Заметок: {notes.length}")
- Реализация через `notes.length` в JSX, без отдельного state
- Итераций: 1
- Обработка случая "0 заметок" — не задавалась явно, поведение определял AI самостоятельно

## Промпт B (структурированный)

```
Роль: ты — senior React/Next.js разработчик, работающий в этом проекте.

Контекст: в app/components/NotesApp.tsx есть список заметок с добавлением и удалением
(state notes: {id, text}[]).

Задача: добавь счётчик количества заметок над списком.

Ограничения:
- Не трогать next.config.ts, tsconfig.json, postcss.config.mjs, eslint.config.mjs
- Использовать только Tailwind utility-классы, без новых зависимостей
- Не менять существующую логику добавления/удаления

Acceptance criteria:
1. Над списком отображается текст вида "Заметок: N"
2. N автоматически обновляется при добавлении и удалении
3. Если заметок 0 — текст "Заметок: 0" (не скрывается)

Формат ответа: краткое описание изменений + сам код.
```

**Результат:**
- Изменения: +5/-1 строк в `NotesApp.tsx`
- Счётчик размещён над списком (после формы), как указано в задаче
- Реализация аналогичная: `notes.length` без отдельного state
- Дополнительно реализована обработка пустого списка: текст "Заметок пока нет" вместо пустого `<ul>`
- Валидация ввода через `trim()` и `canAdd`, сохранена существующая логика
- Итераций: 1
- Ответ AI строго соответствовал заданному формату (описание + код)

## Сравнительная таблица

| Критерий | Промпт A (базовый) | Промпт B (структурированный) |
|---|---|---|
| Формулировка | 1 строка без деталей | Роль + контекст + 3 ограничения + 3 acceptance criteria |
| Итераций до готового результата | 1 | 1 |
| Изменения кода | +5/-1 строк | +5/-1 строк |
| Место размещения счётчика | Выбрано AI произвольно | Задано пользователем |
| Обработка 0 заметок | Не гарантирована | Явно реализована ("Заметок пока нет") |
| Соблюдение технических ограничений | Не проверялось (не задавались) | Явно соблюдены все 3 ограничения |
| Формат ответа | Свободный | Точно по запросу |
| Предсказуемость результата | Низкая | Высокая |

## Выводы

1. **Оба промпта дали технически рабочий код** за одну итерацию — простая задача не показала разницы в затратах токенов на уровне объёма изменений.
2. **Структурированный промпт снижает риск скрытых ошибок**: явные acceptance criteria заставили AI обработать edge-case (0 заметок), который в базовом варианте остался бы на волю случая и мог бы потребовать доп. итерацию при ревью.
3. **Формат ответа предсказуем только со структурированным промптом** — это важно, когда результат должен попасть в отчёт или документацию без дополнительной ручной правки.
4. **Рекомендация**: для простых, некритичных правок базовый промпт экономит время на формулировку; для задач, где важны конкретные требования (edge-cases, стиль кода, формат ответа), структурированный промпт снижает число повторных итераций и, как следствие, расход токенов на всю фичу.
