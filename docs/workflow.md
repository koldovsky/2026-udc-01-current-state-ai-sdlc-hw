# Task 2: фіча «Список нотаток» через режими Plan і Agent

**Інструмент:** Claude Code (розширення для VS Code).
**Фіча:** список нотаток на головній сторінці `app/`. Нотатки зберігаються в `localStorage`, бекенду й нових залежностей немає.

## Acceptance criteria

Сформульовані до написання коду.

1. **Додавання.** Текст + «Додати» або Enter: нотатка одразу з'являється зверху списку, поле очищується.
2. **Валідація.** Порожній текст або лише пробіли не зберігаються; під полем є помилка, яка зникає під час введення. Пробіли по краях обрізаються.
3. **Видалення.** Кнопка «Видалити» прибирає лише свою нотатку. Якщо нотаток немає, показується «Нотаток поки немає».
4. **Збереження.** Нотатки в `localStorage`; після перезавантаження список і порядок ті самі, помилок гідратації в консолі немає.
5. **Правила проєкту.** Сторінка лишається Server Component, `"use client"` лише в компоненті списку, нових залежностей немає, `npm run lint` і `npm run build` без помилок.

Поза обсягом: редагування, пошук, бекенд, автентифікація.

## Режим Plan

Агент не змінював файли проєкту, лише читав:

- `app/AGENTS.md`, поточні `page.tsx`, `layout.tsx`, `globals.css`, `eslint.config.mjs`;
- гайд `preventing-flash-before-hydration.md` з документації встановленої версії Next.js;
- правило `client-localstorage-schema` зі скіла `vercel-react-best-practices`.

Результат: план зі списком файлів, рішеннями та таблицею перевірок за кожним критерієм.

Головне рішення плану стосується гідратації, бо сервер не бачить `localStorage`:

| Варіант | Висновок |
| --- | --- |
| Прямий рендер збережених нотаток | Помилка гідратації |
| `useEffect` + `setState` | Гайд Next.js попереджає про миготіння й зайвий рендер |
| Inline-скрипт із гайду | Без миготіння, але для списку дублює розмітку вручну |
| **`useSyncExternalStore` (обрано)** | Перший рендер збігається із сервером; до гідратації видно «Завантаження…» |

Компроміс обраного варіанта зафіксовано в плані: на повільному з'єднанні «Завантаження…» буде видно до гідратації.

## Рев'ю плану

План затверджено **без правок**, тому коригувань після рев'ю не було.

Під час підготовки плану до нього потрапили вимоги, яких не було в початкових критеріях:

- кнопка «Додати» вимкнена до гідратації, щоб форма не відправилась нативно;
- ключ `localStorage` має версію (`notes:v1`), а пошкоджені дані вважаються порожнім списком;
- `subscribe` слухає подію `storage`, щоб друга вкладка не перезаписала нотатки;
- колір помилки заданий через CSS-змінну, як вимагає конвенція 5 з `app/AGENTS.md`.

## Режим Agent

Агент виконав план у такому порядку:

| Файл | Зміна |
| --- | --- |
| `app/lib/notesStore.ts` | Новий: сховище нотаток на `localStorage` |
| `app/components/NotesList.tsx` | Новий: форма й список, єдиний файл із `"use client"` |
| `app/app/page.tsx` | Шаблон `create-next-app` замінено заголовком і `<NotesList />` |
| `app/app/layout.tsx` | Оновлено `metadata`, `lang="uk"` |
| `app/app/globals.css` | Додано `--danger` для обох тем і `--color-danger` |

Відхилення від плану:

- **Перевірка в браузері.** Окрім ручної перевірки, сценарії виконав агент у headless Chrome через протокол DevTools. Скрипт тимчасовий і в репозиторій не входить, бо нові залежності й тестовий фреймворк не планувалися.
- **Перевірка `package.json`.** План передбачав diff, але `app/` ще не закомічено, тому diff порожній за визначенням. Натомість файл просто не редагувався, а `npm install` не запускався.

## Рев'ю і перевірка

**Команди:** `npm run lint` і `npm run build` завершилися успішно. Маршрут `/` зібрано як статичний.

**Браузер:** 30 перевірок на `npm run dev`, усі пройшли.

| Критерій | Що перевірено |
| --- | --- |
| 1 | Додавання кнопкою й через Enter, нова нотатка зверху, поле очищується |
| 2 | Порожнє поле й самі пробіли дають помилку без нової нотатки; помилка зникає під час введення; `"  текст  "` зберігається як `текст` |
| 3 | Видаляється лише вибрана нотатка; після видалення всіх знову порожній стан |
| 4 | Порядок зберігається після перезавантаження; зіпсований JSON і чужа структура дають порожній список; помилок гідратації в консолі немає |
| 5 | `"use client"` є лише в `NotesList.tsx`; серверний HTML містить «Завантаження…» і вимкнену кнопку |

Додатково перевірено дві вкладки, темну тему, кирилицю й довгий текст без пробілів. Скриншоти агент переглянув окремо.

**Ручна перевірка:** фічу також перевірено власноруч у браузері.

**Зібрана версія:** під час фінальної перевірки агент окремим скриптом пройшов на `next start` 22 перевірки за критеріями 1–5. Усі пройшли, помилок у консолі немає.

**Зауваження з рев'ю (не виправлялися, бо критеріїв не порушують):**

- Поки поле з помилкою у фокусі, замість червоної рамки видно обведення фокусу. Текст помилки при цьому показується.
- Кирилиця відображається шрифтом Arial із `globals.css`, а підключений у `layout.tsx` Geist сторінка не використовує.

**Що не перевірялося:**

- збій запису в `localStorage` (квота, заборона браузера): за планом нотатка в такому разі житиме лише до перезавантаження, без повідомлення користувачу;
- робота в браузерах, відмінних від Chrome.
